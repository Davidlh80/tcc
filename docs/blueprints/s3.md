# Blueprint — Amazon S3

## Objetivo

Definir um template Terraform para um bucket privado, com criptografia, bloqueio de acesso público, transporte seguro e versionamento configurável.

## Estrutura

```text
s3/
├── main.tf
├── variables.tf
├── outputs.tf
├── versions.tf
└── README.md
```

Em `versions.tf`, declarar a versão compatível do Terraform e o provider `hashicorp/aws`. Configurar a região por variável. Em `main.tf`, criar:

| Recurso Terraform                                    | Responsabilidade                                      |
| ---------------------------------------------------- | ----------------------------------------------------- |
| `aws_s3_bucket`                                      | Criar o bucket e aplicar tags                         |
| `aws_s3_bucket_public_access_block`                  | Habilitar as quatro flags de bloqueio público         |
| `aws_s3_bucket_server_side_encryption_configuration` | Configurar SSE-S3 com `AES256`                        |
| `aws_s3_bucket_versioning`                           | Aplicar `Enabled` ou `Suspended`, conforme a variável |
| `aws_s3_bucket_policy`                               | Negar requisições sem transporte seguro               |

Montar a bucket policy com `aws_iam_policy_document`. A negação deve usar `Effect = "Deny"`, principal `*`, ação `s3:*`, recursos do bucket e de seus objetos, e condição `Bool` com `aws:SecureTransport = "false"`. Os wildcards nessa negação não concedem permissões.

## Variáveis

| Nome                 | Tipo          | Obrigatória | Descrição                              |
| -------------------- | ------------- | ----------- | -------------------------------------- |
| `environment`        | `string`      | Sim         | Ambiente: `dev`, `hml` ou `prd`        |
| `system`             | `string`      | Sim         | Identificação do sistema               |
| `region`             | `string`      | Sim         | Região AWS do provider                 |
| `additional_tags`    | `map(string)` | Não         | Tags adicionais; padrão `{}`           |
| `purpose`            | `string`      | Sim         | Finalidade que compõe o nome do bucket |
| `versioning_enabled` | `bool`        | Não         | Habilitar versionamento; padrão `true` |

Construir o nome como `<ambiente>-<sistema>-s3-<finalidade>`. Validar ambiente e componentes; verificar que o nome final atende às regras de nomes do S3. Escolher uma finalidade que torne o nome globalmente único.

## Segurança e governança

- Definir `block_public_acls`, `block_public_policy`, `ignore_public_acls` e `restrict_public_buckets` como `true`.
- Habilitar criptografia `AES256` e negar acesso sem `aws:SecureTransport`.
- Manter `force_destroy = false` para impedir remoção automática de objetos na exclusão do bucket.
- Usar `Enabled` por padrão. Ao desabilitar o versionamento, usar `Suspended`; isso não remove versões existentes.
- Aplicar `Project = "tcc-iac-ia"`, `Environment = var.environment`, `ManagedBy = "terraform"`, `Owner = "devops"` e `CostCenter = "academic-research"`.
- Mesclar tags adicionais antes das obrigatórias para impedir sua sobrescrita.

## Outputs

| Nome          | Valor                 |
| ------------- | --------------------- |
| `bucket_name` | Nome do bucket criado |
| `bucket_arn`  | ARN do bucket criado  |
| `bucket_id`   | ID do bucket criado   |

## Exemplo de configuração

```hcl
environment        = "dev"
system             = "tcc"
region             = "us-east-1"
purpose            = "logs-123456789012"
versioning_enabled = true
additional_tags    = {}
```

Adaptar a finalidade para um nome disponível no ambiente.

## Critérios de aceitação

- As quatro flags de bloqueio público estão habilitadas.
- Criptografia e negação de transporte inseguro estão presentes.
- O versionamento é configurável e habilitado por padrão.
- Nomes, tags, variáveis e outputs atendem ao contexto organizacional.
- O README apresenta visão geral, tabela de variáveis, tabela de outputs e exemplo de uso, nessa ordem.
- Executar `terraform fmt -check`, `terraform init -backend=false` e `terraform validate`; executar Checkov e Trivy conforme o fluxo do repositório e revisar os achados.
